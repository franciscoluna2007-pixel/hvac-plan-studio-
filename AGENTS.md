# Codex project context

- At task start, read `PROJECT_MEMORY.md` when project history, protected behavior, product decisions, or release context matters. Current user instructions and checked-in source take precedence.
- After every meaningful verified update or release, refresh only durable facts in `PROJECT_MEMORY.md`, including the outcome, protected behavior, merged PR/SHA when applicable, and the next step. Do not edit it for trivial work or when there is no new durable context.
- Never store credentials, API keys, personal conversations, emails, customer names, private plan content, or other sensitive data in project memory.
- Keep project memory concise and internally consistent. Replace or remove stale facts instead of accumulating contradictions, and validate the documentation diff before publishing it.
